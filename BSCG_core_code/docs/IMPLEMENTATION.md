# Implementation lineage and scope

Recovered local sources were inspected, including the CowBase external experiment
model/training files and the fold preprocessing implementation. Their file hashes
are listed in `provenance/source_inventory.json`. They are not copied wholesale,
because they contain extra comparator models, experiment-specific paths and
development assumptions. The inventory is evidence of code lineage, not evidence
that the new implementation produced any earlier results.

This release implements the current manuscript's specification with executable
optimisation and evaluation. Components were refactored/reimplemented as needed;
new code is not described as a recovered historical training snapshot.

| Aspect | Recovered CowBase development code | This release/current manuscript |
|---|---|---|
| Sensor/static readout | Separate static path and gated fusion | Sensor vector plus static features through one fusion head |
| Local representation | Segment summaries plus gated local encoder | Local projection, attention and mean pooling |
| Auxiliary coefficient | Warmup after early epochs | Fixed0.02 throughout training |
| Shuffled validation | Five draws in recovered protocol | Twenty draws per seed |
| Architecture counts | Depend on development gates/heads | 29,825 MMCOWS;29,889 CowBase for full model |
| Input provenance | Version-specific prepared inputs | Caller-supplied generic arrays with overlap checks |
| Selected settings | Specific development-run outputs | Selected afresh using development partitions |

The provided JSON files describe search spaces and fixed architecture, not
claimed trained configurations. Actual selected settings, epochs and checkpoint
weights are generated by training. Values from drafting tables are not used as
training targets or hardcoded results.

Round-robin inner cow groups over sorted remaining IDs reproduce the manuscript
grouping for its ordered cow IDs. Arbitrary caller IDs produce their own
deterministic grouping. Export the generated local manifest for exact replay.
CowBase uses the documented SHA-256 integer-ID holdout rule and temporal limits.

The release covers the BSCG architecture, core variants, model selection,
inference, fixed baselines and Table 2 import/export. It does not implement
Transformer/LSTM/TCN/HGB training, the capacity-matched generic comparator or
every supplementary frozen perturbation analysis. Those should come from the
final experiment repository if they are part of the intended public release.

Reference documentation consulted: PyTorch's TransformerEncoderLayer API
(https://docs.pytorch.org/docs/stable/generated/torch.nn.TransformerEncoderLayer.html)
and the dataset provider links. No third-party repository is represented as the
authors' original BSCG implementation.
